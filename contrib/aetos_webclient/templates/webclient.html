{% extends "aetos/base.html" %} {% load static aetos_tags %} {% comment %} Aetos Web Client page. This template wins over Evennia's own `webclient.html` because a game prepends the Aetos template directory to `TEMPLATES[0]["DIRS"]` (see README.md). It cannot be found by the app-directory loader alone: Django searches every DIRS entry before any installed app, and Evennia always has its own webclient template directory in DIRS. Aetos extends its own base (`aetos/base.html`) rather than Evennia's stock `webclient/base.html`. The stock base loads eight third-party CDN resources for the benefit of the stock GUI; Aetos is vanilla JavaScript and uses none of them. See `aetos/base.html` for the full reasoning. Evennia's transport is still entirely untouched: `evennia.js` is loaded unmodified from Evennia's own static files, and the Portal is not involved. {% endcomment %} {% block styles %} {% endblock %} {% block scripts %} {% comment %} The accessibility subsystem loads before everything else. A11Y-NAV-001. First in the document, because that is the only position that helps: a skip link a keyboard user reaches after tabbing through the interface has skipped nothing. They are visually hidden until focused, so they cost sighted players nothing and save keyboard players the entire widget tree. Ordered by how often someone needs them. The command input comes first because it is where a player wants to be nearly every time. {% endcomment %}

This is the navigation landmark, and A.50 requires that it stay in the same place regardless of which workspace is active -- someone who is lost should not have to find the help button somewhere new. role="toolbar" would be wrong here: these are unrelated controls, not a group sharing one arrow-key model. {% endcomment %}
{% comment %} The two announcement regions. Addendum A.15, A11Y-ANN-001. These are the only live regions in Aetos. Widgets never create their own: a player has one pair of ears and one braille display, so thirty independent live regions do not produce thirty conversations, they produce one conversation with thirty interruptions in render order. The urgent region interrupts and is reserved for connection and session failure. Gameplay never reaches it -- a channel that interrupts constantly stops being an interruption, and then the one message that truly needed to interrupt is the one that gets ignored. {% endcomment %}
{% comment %} Regions are created by the layout adapter, and widgets are mounted into them from the registry -- see builtins.js. Blueprint section 46 requires named regions for a screen-reader layout; the adapter gives every widget panel a heading and an accessible name, so the landmark structure survives the move to dynamic mounting. {% endcomment %}
